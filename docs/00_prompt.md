# ジャンル選定プロンプト（実行版）

このファイルは、今回のジャンル選定で実際に使ったプロンプトをまとめたものです。
次に別の目標や条件で選び直すときは、「前提」の部分を書き換えて、もう一度実行してください。

---

## 前提（毎回書き換える部分）

- 目的: 個人が新しくアフィリエイトサイトを立ち上げる。立ち上げから12〜18ヶ月で、確定報酬ベースで月10万円を目指す。
- 日付: 2026年10月31日
- 会話で決めた条件
  1. 固有名詞の組み合わせで検索される言葉が大量にある（「車種名＋維持費」のように、組み合わせでページを量産できる）
  2. 検索上位に大手ではなく、個人サイトや古いページが混ざっている（企業のオウンドメディアや予約・比較サイトが独占しているジャンルは避ける）
  3. A8.net に成果単価の高い提携先がある
  4. すでに個人で稼いでいる成功者がいて、真似できそうな業界
  - 補足: 信頼できる公的データがあるか（注文住宅の坪単価は、データの出どころがないので保留）
- 追加の要望: AIで作ったとまるわかりなサイトは避けたい（文章もデザインも）

## 守ること

- 根拠のない数字は作らない。推定の数字には「推定」と書き、何と何を掛けたのかを添える。
- 確認できなかったことは「未確認」と書く。
- 主張には出典URLを付ける。
- 検索結果の順位は、日本のGoogleと一致しない近似だと明記する（今回の環境ではWeb検索しか使えず、検索ページを直接開けないため）。

## 手順

### 1. 条件そのものを見直す（4つの観点で並行して検討し、1つに統合する）

| 観点 | 何を調べるか |
| --- | --- |
| 2024〜2026年の検索環境 | 大量生成コンテンツに関するGoogleのポリシー、コアアップデートの影響、AI Overviewsでクリックがどれだけ減るか、ページを量産するサイトが生き残る条件 |
| 収益の仕組み | 月10万円から逆算した必要PV、A8以外のASP、案件の停止や単価改定のリスク、承認率、検索意図と申し込みの近さ |
| 現行条件の妥当性 | 測れる条件か、条件同士が矛盾しないか（条件2と条件4など）、生存者バイアス、古い成功例をあてにしていないか |
| 運営・法律・AIっぽさ | ステマ規制のPR表記、YMYL、広告規制、公的データの利用規約、更新の手間、一次情報の入れやすさ |

統合するときは、条件を8〜11個にまとめ、重み（合計100）、必須かどうか、Web検索だけで確かめる方法、0〜5点の採点基準を付ける。元の条件1〜4と補足条件は、それぞれ「維持・修正・統合・格下げ・削除・格上げ」のどれにするかを、理由を付けて決める。

### 2. 候補を5つの起点から出す（条件の見直しと並行して進める）

- 公的データから考える（e-Stat、国交省、厚労省、自治体のオープンデータなど）
- 高単価の案件から考える（A8.netなど）
- 個人の成功例から考える（収益報告、サイト売買、データベース型サイト）
- 「固有名詞×属性」のキーワードの組み合わせから考える
- 「地域×サービス・制度」から考える（補助金、一括見積もりなど）

### 3. 候補を絞る

重複をまとめて12件に絞る。比較のため、会話で挙がった「車種×維持費」と「ハウスメーカー×坪単価」もベースラインとして加える。

### 4. 候補ごとに確かめる（根拠集め → 反証）

- 根拠集め: Web検索を10〜15回使う。組み合わせクエリでの上位の顔ぶれ、A8と他ASPの報酬、公的データの形式と利用規約、2024〜2026年の個人の成功例、月10万円までの逆算、AI Overviewsに答えを持っていかれないか、一次情報で差をつけられるかを、各条件0〜5点で採点する。
- 反証: 別のエージェントが独立に6〜10回検索し、甘い評価を崩しにいく。最後に条件ごとの点数を付け直し、致命的な欠陥があるかを判断する。
- 加重平均は、エージェントではなくコードで計算する。必須条件が1点以下の候補は除外する。

### 5. 審査とサイト設計

- 3人の審査員が別々の観点で全候補を順位付けする（月10万円への速さと確実さ／長く稼げるか／個人で実行できるか・AIっぽくならないか）。
- 最終担当が推奨ジャンル1つと次点2つを決め、レポート、候補と条件の表、推奨ジャンルのサイト設計（URL設計、ページのひな形、データ源、最初の30ページ、収益化の配置、AIっぽく見せない工夫、法務、12ヶ月の計画）を出す。

### 6. サイトを形にする

- デザインは taste-skill の進め方に従う：題材から方向性を3案出して選び、コピーを先に書き、ありがちな装飾（グラデーション、アイコン付きカードの羅列、小さな英字ラベル、絵文字など）を使わず、3つの画面幅で見た目を確かめる。
- ページを量産する部分は、公的データ（JSON）とひな形から静的HTMLを生成する。ページごとに固有の数値、出典、更新日を必ず載せる。
