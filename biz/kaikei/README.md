# ひきつぎ会計

町内会・自治会、子ども会、PTA、サークルなどの「会計係」のための、ブラウザで動く道具と、その紹介のページです。

## これは何か

- **だれの**: 毎年交代する、無償の会計係。簿記にも表計算ソフトにも慣れていない方。
- **どんな困りごと**: 総会の前に、通帳と領収書から決算書を作るのがたいへん。次の担当への引き継ぎも、毎年うまくいかない。
- **どう解くか**: 収入と支出を1件ずつ入れるだけで、総会の資料5種類（収支決算書、出納帳、会計監査報告書、次年度の予算案、引き継ぎ書）ができる。帳簿のすべてが「ひきつぎファイル」1つに入り、次の担当は、そのファイルを開けば続きから始められる。
- **データの置き場所**: 登録なし。サーバーなし。入力した内容は、使う人のブラウザの中と、その人が保存したファイルにだけある。運営者は見られない。
- **向いていない団体**: 税の申告、法人格のある団体（NPO法人、認可地縁団体など）、収益事業のある団体、複式簿記、会計を2つ以上に分けている団体、2人以上で同時に入力したい団体。
- **料金**（`src/site.config.ts` の `pricing`）
  - 無料: 入力、集計、残高の照合、資料の画面での確認、ファイルの保存と読み込み、印刷（紙に「見本」の透かしが入る）。
  - 1年度ぶん 980円（税込）: 透かしなしの印刷と、次の年度への繰り越し。ライセンスキーは、発行した日から400日使える。

サイトのページは4つです。

| URL | 中身 |
| --- | --- |
| `/` | 紹介のページ（ランディングページ）。見本の資料は、道具と同じ部品とロジックで描いている |
| `/app` | 道具の画面。`/app#sample` で開くと、サンプルの帳簿が入った状態で始まる |
| `/tokushoho` | 特定商取引法にもとづく表記 |
| `/privacy` | プライバシーポリシー |

## 動かす

Node.js（バージョン 20 以上）がいります。

```sh
npm install
npm run dev            # 開発用。http://localhost:5173
npm run build          # ページごとの静的HTMLを dist/ に書き出す
npm run serve          # dist/ を http://localhost:4173 で確かめる
npm run build:single   # 全ページを dist-single/index.html の1ファイルにまとめる（確認用。ダブルクリックで開ける）
npm test               # 計算のテスト
npm run typecheck
```

## フォルダの中身

- `src/site.config.ts` … サービス名、URL、決済ページ、運営者の情報、料金。**公開前に埋める項目は、ここに集めてある。**
- `src/routes.ts` … ページの一覧と、検索結果に出る題と説明。ここに足したページが `dist/<パス>/index.html` になる。
- `src/core/` … 計算、判定、保存の形式、サンプルのデータ（画面に依存しない TypeScript）。使い方と設計は `src/core/README.md`。
  - `sources.ts` … ページに書いた事実の出典。`notices.ts` … 対象外のこと、ことわり書きなど、道具と紹介のページで共通の文。
- `src/pages/` … ページ。`Landing.tsx`（`/`）、`Tool.tsx`（`/app`）、`Tokushoho.tsx`、`Privacy.tsx`。
- `src/components/landing/` … 紹介のページと、特商法・プライバシーポリシーの部品（見出し、いちばん上、資料の見本、照合の見本、引き継ぎ、料金、よくある質問、フッター）。`demo.ts` は、見本に使う帳簿。
- `src/components/tool/` … 道具の画面（はじめの画面、入力と一覧、科目と予算、残高の照合、資料、引き継ぎ）。
- `src/components/papers/` … 総会の資料5種類の「紙」。道具の画面と、紹介のページの見本の両方で使う。
- `src/components/ui/` … 21st.dev から取り入れて作り変えた部品と、朱のはんこ（`seal.tsx`）。何をどう変えたかは `CREDITS.md`。
- `src/index.css` … 色・書体・角の丸み・影（「帳簿と、朱のはんこ」）。`src/styles/paper.css` … 資料の紙と、印刷（A4 縦）。`src/styles/landing.css` … 紹介のページだけの決まり。
- `src/lib/license.ts`、`scripts/license.mjs` … 有料版のライセンスキー（サーバーなしで確かめる）。
- `public/` … `favicon.svg`（しるし）、`og.png`（SNS などで共有されたときの画像）、`robots.txt`。
- `scripts/og.html`、`scripts/og.cjs`、`scripts/og-build.mjs` … 共有画像を作るためのもの（下の「共有画像を作り直す」）。

## 公開前に、運営者がやること

上から順に進めてください。コマンドは、このフォルダ（`biz/kaikei`）で打ちます。

### 1. `src/site.config.ts` の空の項目を埋める

文字は、`''` の間に書きます（例: `contact: 'info@example.com',`）。

| 項目 | 書くこと | 空のままだと |
| --- | --- | --- |
| `baseUrl` | 公開するURL。最後の `/` は付けない（例: `https://hikitsugi.example.com`） | 共有画像（og.png）と、`sitemap.xml` が出ない |
| `checkoutUrl` | 決済ページのURL（下の 3） | 購入のところが「販売準備中です」と出る |
| `licensePublicKey` | ライセンスの公開鍵（下の 2） | 「公開前モード」になり、だれでも有料版のはたらきを使える |
| `contact` | お問い合わせ先（メールアドレス、またはフォームのURL） | よくある質問の「ここにない質問は…」が出ない。プライバシーポリシーのお問い合わせ先は、`operator.email` も空なら「（公開前に記入します）」と出る |
| `legalUpdatedOn` | 特商法の表記とプライバシーポリシーを定めた日（例: `2027年1月15日`） | 「（公開前に記入します）」と出る |
| `operator.name` ほか5つ | 販売事業者の名前、運営責任者、所在地、電話番号、メールアドレス | 特商法のページに「（公開前に記入します）」と出る |
| `sales.environment` | 動作環境。**自分で動きを確かめたブラウザだけ**を書く（下の 6） | —（はじめから文が入っている。Chrome だけを確かめた、という文） |

`slug`（`'kaikei'`）は、変えないでください。保存したデータとライセンスキーが、使えなくなります。

料金を変えるときは、`pricing`（金額、日数）と `sales`（特商法の文）の両方を直します。紹介のページ、道具の画面、検索結果の説明は、ここから数字を読みます。

### 2. ライセンスの鍵を作る（1回だけ）

```sh
node scripts/license.mjs keygen
```

- 画面に出た長い文字（公開鍵）を、`src/site.config.ts` の `licensePublicKey` に貼ります。
- 同じフォルダに `.license-private.json`（秘密鍵）ができます。**これは、だれにも渡さず、Git にも入れません**（入らない設定になっています）。USB メモリなど、別の場所に控えを取ってください。
- 秘密鍵をなくすと、新しいキーを発行できなくなります。鍵を作り直すと、**それまでに売ったキーが、すべて使えなくなります。**
- 公開鍵を入れると、「公開前モード」が終わり、キーを入れた人だけが有料版になります。入れたあとは、もう一度ビルドして、公開し直してください。

### 3. 決済ページを作る

Stripe の「支払いリンク（Payment Link）」などで、次の内容の決済ページを作り、そのURLを `checkoutUrl` に入れます。

- 商品の名前: ひきつぎ会計 1年度ぶん
- 金額: 980円（税込）。1回払い（毎月の支払いにしない）
- 買う人に書いてもらうこと: メールアドレスと、**団体の名前**（キーに入れるため。書いてもらう欄を足せないときは、購入のあとのメールでたずねます）
- 支払いが終わった画面に出す文の例: 「ありがとうございます。ライセンスキーを、メールでお送りします。」

`src/site.config.ts` の `sales`（支払方法、引渡し時期、返品）を、実際の売り方に合わせて見直してください。

### 4. 買ってもらったら、キーを発行して送る

注文が入るたびに、次のコマンドを打ちます。団体の名前は、買った方のものに変えます。

```sh
node scripts/license.mjs issue --name "みどり町内会" --days 400
```

- 1行目に、キーの中身（団体の名前、発行日、期限）が出ます。2行目の長い文字が、ライセンスキーです。
- キーを、買った方にメールで送ります。メールの文の例:

  > ライセンスキーをお送りします。ひきつぎ会計の「引き継ぎ」の画面の「有料版」のところに、下のキーを最初から最後までコピーして、貼り付けてください。キーは、ひきつぎファイルの中に保存されるので、次の担当の方も、期限（◯年◯月◯日）まで使えます。

- 送る前に、キーが正しいか確かめられます: `node scripts/license.mjs verify "キー"`
- キーは400日で切れます。次の年度も使う団体には、あらためて買ってもらいます。
- キーは、ブラウザの中だけで確かめています（サーバーがないため）。キーを写せば、ほかの団体でも使えてしまいます。それを止めるしくみは、ありません。

### 5. ビルドして、公開する

```sh
npm run typecheck && npm test && npm run build
```

- `dist/` の中身が、公開するファイルのすべてです。静的なファイルを置けるサービスなら、どこでも公開できます。
- Vercel に置くときは、プロジェクトの設定の「Root Directory」を、このフォルダ（`biz/kaikei`）にします。`vercel.json` の設定（`/app` で `dist/app/index.html` を返す、など）が、そのまま使われます。ほかのサービスでは、「`/app` で `app/index.html` を返す」設定になっているかを確かめてください。
- **必ず https で公開してください。** http では、ライセンスキーの確かめが動きません。
- ドメインを決めたら、`baseUrl` に入れて、もう一度ビルドします。
- `site.config.ts` を直したあとは、いつも、ビルドと公開をやり直します。

### 6. 公開の前に、確かめておくこと

作るときに確かめられたのは、Chrome と同じしくみのブラウザ（Chromium）の、パソコンとスマートフォンの画面の大きさだけです。次のことは、**まだ、だれも確かめていません。**

- [ ] **ほかのブラウザと、本物のスマートフォン**（iPhone の Safari、Android の Chrome、Edge、Firefox）で、入力 → 資料 → ファイルに保存 → ファイルを開く、が動くこと。確かめたブラウザを、`sales.environment` に書き足す。
- [ ] **本物のキーボード**で、取引の入力のとき、日本語を変換している途中の Enter キーで、次の欄へ進んでしまわないこと。
- [ ] **本物のプリンター**で、資料が A4 にずれずに出ること。無料版の「見本」の透かしが出ること（ブラウザの印刷の設定によっては、出ないことがあるかもしれません）。
- [ ] **決済からキーまでの流れ**を、自分で1回通すこと（買う → キーを発行 → メール → 道具に入れる → 透かしが消える → ファイルに保存 → 別のブラウザで開いても有料版になる）。
- [ ] **出典を、ページを開いて確かめること。** `src/core/sources.ts` の5件は、作業した環境から役所のサイトを開けなかったため、検索結果に出た抜粋でしか確かめられていません。URL を開いて、`claim` の文と合っていることを確かめ、`how` を `'page'` に、`checkedOn` を確かめた日に書きかえてください。書きかえると、紹介のページの「参考にした公の資料」が「出典」に変わり、「確かめが済んでいない資料を含みます」の文が消えます。合っていなければ、`src/core/notices.ts` の文を直します。
- [ ] **プライバシーポリシー**（`src/pages/Privacy.tsx`）が、実際のやり方と合っていること。とくに、サイトを置くサービスのアクセスの記録の扱いと、書体を Google Fonts から読み込んでいること。アクセス解析や広告を入れるなら、書き直しがいります（紹介のページの「入れていません」の文も）。
- [ ] **特商法の表記**（`/tokushoho`）に、「（公開前に記入します）」が残っていないこと。
- [ ] **サンプルの団体名**「あおぞら町内会」と役員の名前は、作ったものです。同じ名前の実在の団体から問い合わせがあったら、`src/core/sample.ts` の名前を変えてください。
- [ ] **無料版の見え方。** 公開前モードのあいだは、道具の画面のいちばん上の「無料版の表示を確かめる」で見られます。

### 7. 共有画像を作り直す（文や見た目を変えたとき）

`public/og.png`（1200×630）は、`scripts/og.html` を画面に出して撮ったものです。

```sh
node scripts/og-build.mjs   # サンプルの本物の収支決算書を入れた scripts/og.html を作り直す
node scripts/og.cjs         # scripts/og.html を撮って、public/og.png に書き出す（Playwright がいる）
```

見出しの文や割りつけを変えるときは、`scripts/og-build.mjs` の中のひな形を直します。

## 公開したあと

- **問い合わせ**: 運営者は、利用者の帳簿を見ることも、元に戻すこともできません。「データが消えた」という問い合わせには、保存したひきつぎファイルを開いてもらうしかありません。
- **保存の形式を変えるとき**: `src/core/types.ts` の `FILE_VERSION` を上げて、`src/core/validate.ts` に、古いファイルの直し方を足します。古いファイルが開けなくなる変更は、しないでください（利用者の帳簿は、利用者の手元にしかありません）。
- **できていないこと**は、`src/core/README.md` の「できていないこと・あやしいところ」に、まとめてあります。
