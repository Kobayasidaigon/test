# たたき台シフト

## これは何か

スタッフ5〜20人の個人経営の店（美容室、飲食店、調剤薬局、クリニック、小売など）の店長・オーナーが、毎月 Excel や紙で組んでいるシフト表の「組む作業」だけを肩代わりする道具です。

- **だれの、どんな困りごとか**: 希望休と必要な人数を見くらべながら、毎月シフト表を手で組むのに時間がかかる。
- **どう解くか**: 希望休と必要な人数を入れてボタンを押すと、条件（休み希望、定休日、連勤の上限など）を守った「たたき台」を、ブラウザの中で数秒で組みます。足りない日は、何日のどの勤務に何人足りないか、なぜ入れる人がいないかを文で出します。
- **やらないこと**: シフト管理のサービスではありません。スタッフ用のアプリ、会員登録、月額の料金、勤怠の打刻、給与の計算はありません。希望休は今までどおり紙や LINE で集め、できた表は印刷して貼ります。法令に合っていることの保証もしません。
- **データ**: サーバーはありません。入れた内容は、使う人のブラウザの中だけに保存され、ファイル（JSON）にして持ち運べます。
- **料金**（`src/site.config.ts` の `pricing`）:
  - 無料: スタッフ8人まで。自動作成、手直し、点検、理由の説明、印刷、ファイルへの保存と読み込み。期限なし。
  - 買い切り 4,980円（税込）: スタッフ9人以上（30人まで動作を確かめてあります）、CSV の書き出し、翌月への引き継ぎ。月額なし、キーに期限なし。

サイトは、ランディングページ（`/`）、道具の画面（`/app`）、特定商取引法にもとづく表記（`/tokushoho`）、プライバシーポリシー（`/privacy`）の4ページです。

## 動かす

```sh
npm install
npm run dev            # 開発用。http://localhost:5173
npm run build          # ページごとの静的HTMLを dist/ に書き出す
npm run serve          # dist/ を http://localhost:4173 で確認する（node scripts/serve.mjs 4310 のようにポートを決められる）
npm run build:single   # 全ページを dist-single/index.html の1ファイルにまとめる（確認用。ダブルクリックで開ける）
npm test               # 計算のテストと、LP の見本が本物の計算と同じかのテスト
npm run typecheck
npm run snapshot       # LP の見本（サンプルを組んだ結果）を作り直す。下の「LP の見本」を見ること
```

公開するのは `dist/` の中身です（`vercel.json` は Vercel 用の設定。ほかの静的ホスティングでも、`dist/` を置けば動きます）。

## フォルダの中身

- `src/site.config.ts` … サービス名、URL、決済ページ、運営者の情報、料金（`pricing`、`plans`、`sales`）。**公開前に埋める項目は、ここに集めてあります。** 料金の数字は、ここだけを変えます（LP、道具の中の案内、特定商取引法の表記、検索結果に出る文が、ここを見ます）。
- `src/routes.ts` … ページの一覧と、検索結果に出る題（title）と説明（description）。ここに足したページが `dist/<パス>/index.html` になります。
- `src/core/` … 中身のロジック（データの型、自動作成、点検、組めない理由の説明、保存と読み込み、サンプル）。画面に依存しません。使い方は `src/core/README.md`。 `handcheck.test.ts` は、小さな店をまるごと1つ作り、紙の上で先に出した答え（足りない日数、勤務時間、2024年の祝日など）と、計算の結果が合うかを確かめるテストです。
- `src/pages/` … ページ。
  - `Landing.tsx` … ランディングページ。中身は `src/components/landing/` にセクションごとに分けてあります。
  - `Tool.tsx` … 道具の画面（/app）。保存と読み込み、手順の切りかえ、自動作成の進行をまとめています。
  - `Tokushoho.tsx`、`Privacy.tsx` … 特定商取引法にもとづく表記、プライバシーポリシー。
- `src/components/landing/` … ランディングページの部品。
  - `site-header.tsx`、`site-footer.tsx` … 上のナビと、下のフッター（LP とそのほかのページで共通）。
  - `hero.tsx`、`hero-demo.tsx` … 一番上の見出しと、動く見本（サンプルの店で、本物の自動作成をページの中で動かす）。
  - `about.tsx`（どういう道具か）、`how.tsx`（使い方の3ステップ）、`reasons.tsx`（組めないときは理由を言う）、`limits.tsx`（できないこと）、`data.tsx`（データの扱い）、`pricing.tsx`（料金）、`faq.tsx`（よくある質問）。
  - `legal-page.tsx` … 文だけのページ（特商法、プライバシー）の枠。
  - `demo-data.ts`、`demo-build.ts`、`demo-snapshot.ts`、`demo-snapshot.test.ts` … LP の見本（下の「LP の見本」）。
- `src/components/tool/` … 道具の画面の中身（はじめの画面、①〜④の手順、印刷用の表、ファイルを開く、買い切り版の案内）。
- `src/components/shift-grid.tsx`、`shift-block.tsx`、`logo.tsx` … シフト表・勤務のブロック・印。道具の画面と LP の両方で使います。
- `src/components/ui/` … 21st.dev から取り入れて、作り変えた部品。出どころと変えたところは `CREDITS.md`。
- `src/index.css` … 色・書体・角の丸み・影のトークンと、シフト表（`.sg`）・ブロック（`.blk`）・印刷（`.pt`）・LP（`.lp-…`）の見た目。
- `src/lib/license.ts`、`src/lib/use-license.ts`、`scripts/license.mjs` … 有料版のライセンスキー（サーバーなしで確かめる仕組み）。
- `public/favicon.svg`、`public/og.png` … サイトの印と、SNS などで共有されたときに出る画像（1200×630）。`og.png` のもとは `scripts/og.html`。
- `public/404.html` … ないURLが開かれたときに出るページ（Vercel などの静的ホスティングが、`dist/404.html` を返します）。React を使わない1枚だけのHTMLで、サービスの名前・色・書体を手で書いてあります。名前や色を変えたら、ここも直してください。
- `scripts/` … `prerender.mjs`（静的HTMLの書き出し）、`serve.mjs`（確認用のサーバー）、`license.mjs`（ライセンスキー）、`make-demo-snapshot.ts`（LP の見本を作り直す）、`og.html`（共有画像のもと）。

## LP の見本について

LP に出てくるシフト表は、どれも絵ではなく、道具と同じ部品（`ShiftGrid`）に、サンプルの店のデータを入れたものです。

- **一番上の「動く見本」**は、「組んでみる」を押すたびに、道具と同じ自動作成をページの中で動かします。開いた端末の「来月」の表になります。
- **「使い方の3ステップ」と「組めないとき」の見本**は、2026年12月のサンプルを自動作成で組んだ結果を、あらかじめファイル（`src/components/landing/demo-snapshot.ts`）にしたものです。LP を開くたびに自動作成を何回も回すと、遅いスマホではページが止まってしまうためです。
- このファイルが本物の計算と同じであることを、`npm test`（`demo-snapshot.test.ts`）が毎回確かめます。**自動作成（`src/core/solver.ts`）やサンプル（`src/core/samples.ts`）を変えて、このテストが落ちたら、`npm run snapshot` で作り直してください。**
- 見本の年月は `src/components/landing/demo-data.ts` の `DEMO_YEAR` と `DEMO_MONTH` です。

共有画像（`public/og.png`）を作り直すときは、`scripts/og.html` をブラウザで開き、幅1200×高さ630 の大きさでそのまま画面を撮って、`public/og.png` に上書きします（手順は `og.html` の先頭にも書いてあります）。LP の見出しを変えたら、`og.html` の文も合わせてください。

## 公開前に、運営者がやること

上から順に進めてください。**4〜6 は、同じ日にまとめて行います**（決済ページだけ先に出すと、キーを受け取れない人が出ます。公開鍵だけ先に入れると、買えないのに有料の機能が閉じます）。

### 1. ドメインを決めて、`baseUrl` を入れる

1. ドメインを取り、ホスティング（Vercel など）に `dist/` を公開する設定をします。Vercel なら、このフォルダ（`package.json` と `vercel.json` があるフォルダ）を「公開するフォルダ（Root Directory）」に指定すると、`vercel.json` の設定（`npm run build` して `dist/` を公開）が使われます。
2. `src/site.config.ts` の `baseUrl` に、公開する URL を入れます（最後の `/` は付けません）。

   ```ts
   baseUrl: 'https://example.jp',
   ```

   これで、検索エンジン向けの正式な URL（canonical）、共有画像の URL、`sitemap.xml` が出るようになります。空のままでも動きますが、SNS で共有したときに画像が出ません。

### 2. お問い合わせ先と、運営者の情報を入れる

`src/site.config.ts` の次の項目を埋めます。空のあいだは、特定商取引法にもとづく表記に「（公開前に記入します）」と「このページは、準備中です」が出ます。

```ts
contact: 'お問い合わせ用のメールアドレス、またはフォームのURL',
operator: {
  name: '販売事業者の名前（屋号や氏名）',
  representative: '運営責任者の氏名',
  address: '所在地',
  phone: '電話番号',
  email: 'メールアドレス',
},
```

### 3. 特定商取引法の表記と、プライバシーポリシーを読み直す

- `/tokushoho` の中身は `site.config.ts` の `sales` です。返品・返金の条件、引渡し時期などが、自分の売り方に合っているかを確かめ、合わなければ直します。**ここに入っている文は、ひな形です。法律に合っているかは、ご自身で（必要なら専門家に）確かめてください。**
- `/privacy`（`src/pages/Privacy.tsx`）は、「入力した内容はサーバーに送らない」「アクセス解析や広告を使わない」「書体は Google Fonts から読み込む」「決済は Stripe」という今の作りに合わせて書いてあります。アクセス解析を入れる、決済の会社を変える、といったときは、文も直してください。

### 4. 決済ページを作って、`checkoutUrl` を入れる

1. Stripe に登録し、管理画面で「支払いリンク（Payment Links）」を作ります。商品は「たたき台シフト 買い切り版」、金額は 4,980円（税込）、**1回だけの支払い**（定期の支払いにしない）にします。
2. 買った人の店名（または名前）をキーに入れるので、支払いリンクの設定で、店名を書いてもらう欄を足しておくと楽です。
3. できた支払いリンクの URL を `src/site.config.ts` の `checkoutUrl` に入れます。

   ```ts
   checkoutUrl: 'https://buy.stripe.com/…',
   ```

   空のあいだは、LP と道具の中の購入ボタンが「販売準備中」（押せない）になります。入れると「買い切り版を買う」のボタンになります。

料金を変えるときは、Stripe の金額と `site.config.ts` の `pricing.pro.priceYen` を、必ず両方変えてください。

### 5. ライセンスの鍵を作って、`licensePublicKey` を入れる

買い切り版は、運営者が発行した「ライセンスキー」を、買った人が道具の画面に入れると使えるようになります。サーバーは要りません。

1. このフォルダで、次を1回だけ実行します。

   ```sh
   node scripts/license.mjs keygen
   ```

2. `.license-private.json` というファイルができます。これが**秘密鍵**です。
   - Git には入りません（`.gitignore` に入っています）。**人に渡さない・公開しないでください。**
   - **なくすと、新しいキーを発行できなくなります。** 作り直すと、発行済みのキーがすべて使えなくなります。USB メモリなど、別の場所に必ず控えを取ってください。
3. 画面に出た**公開鍵**（長い英数字）を、`src/site.config.ts` の `licensePublicKey` に貼ります。

   ```ts
   licensePublicKey: 'MFkwEwYH…',
   ```

4. `npm run build` をやり直して、公開します。

公開鍵を入れると「公開前モード」（有料の機能がすべて試せる状態）が終わり、キーを入れていない人は無料版になります。

### 6. キーの発行のしかた（売れるたびに行う）

1. Stripe から、支払いがあったという知らせが届きます。買った人のメールアドレスと、店名（または名前）を確かめます。
2. このフォルダで、次を実行します（`--days` は付けません。付けると期限つきのキーになります。買い切りなので、期限なしで発行します）。

   ```sh
   node scripts/license.mjs issue --name "山田美容室"
   ```

3. 画面に出た長い文字（キー）を、最初から最後までコピーして、買った人にメールで送ります。メールには、入れ方も書いておくと親切です:「道具の画面の右上から『買い切り版について』を開いて、キーを貼り付け、『キーを確かめる』を押してください」。
4. キーが正しいかを自分で確かめたいときは、次のようにします。

   ```sh
   node scripts/license.mjs verify <キー>
   ```

特定商取引法の表記には「決済の完了後、ライセンスキーをメールでお送りします」と書いてあります。送るのが手作業であること（すぐには届かないこと）を、買う人にわかるように書き足すかどうかも、決めてください。

### 7. 公開の前に、確かめておくこと

作るときに確かめられなかったことが、いくつかあります。公開の前に、ご自身で確かめてください。

- **買う流れを、1回通す。** Stripe のテスト用の設定で支払い → キーを発行 → 道具の画面に入れる → 9人めのスタッフを足せる・CSV を書き出せる・翌月へ引き継げる、まで。
- **無料版の見え方。** 公開鍵を入れる前なら、道具の画面のいちばん下の「無料版の表示を確かめる」で切りかえられます。
- **Chrome 以外のブラウザ。** 動作を確かめたのは、Chrome と同じしくみのブラウザ（Chromium）だけです。Safari（Mac、iPhone）、Firefox、Edge、実物のスマホでは確かめていません。とくに、Safari で印刷が横向きになるか、スマホで表が横に動かせるか、を見てください。確かめたら、`site.config.ts` の `sales.environment`（特商法の「動作環境」）と、LP の「よくある質問 › どのブラウザで使えますか」（`src/components/landing/faq.tsx`）の文を直してください。
- **Excel からの貼り付け。** タブ区切りの文字では確かめましたが、本物の Excel からコピーして貼り付ける確かめは、していません。
- **祝日の出典。** 祝日の計算は、内閣府「国民の祝日について」と国立天文台の暦要項の一覧に合わせてあります（出典は `src/core/holidays.ts` の `HOLIDAY_SOURCES`。LP の「よくある質問」にも出しています）。作るときの環境からは、この2つのページを直接開けませんでした。ブラウザで開いて、日付が合っているかを見直してください。来年の祝日が発表されたとき（毎年2月ごろ）にも、見直してください。
- **LP の見本の月。** 「使い方」と「組めないとき」の見本は、2026年12月のサンプルのままです（一番上の「動く見本」だけが、開いた端末の「来月」になります）。月日がたって古く見えるようになったら、`src/components/landing/demo-data.ts` の `DEMO_YEAR` と `DEMO_MONTH` を変えて、`npm run snapshot` で作り直してください。「どういう道具か」の絵（`about.tsx`）の「12月の希望休」と、共有画像（`scripts/og.html`）の月も、手で合わせます。
- **サンプルの月。** サンプルの店は、2026年12月〜2027年12月の月で確かめてあります。それより先の月では、祝日の並びによって、美容室や薬局のサンプルにも「足りない日」が出ることがあります（道具としては正しい動きですが、見本としては見直しどきです）。
- **LP に書いたことが、今も本当か。** 道具を変えたら、LP の文（とくに「できること／できないこと」「よくある質問」）も合わせてください。LP には、道具で実際に動くことだけを書いています。利用者の声、導入数、「No.1」などは、ひとつも入れていません。足すときは、本当のものだけにしてください。

## 画面の作り（道具）

- 最初に開くと「サンプルで試す」（美容室・飲食店・薬局）と「自分の店で始める」。
- 手順は4つ: ①店とスタッフ → ②必要な人数と条件 → ③希望休 → ④シフト表。行き来は自由。
- ④で「シフトを組む」を押すと、Web Worker の中で自動作成が走ります。マスを押すと勤務を変えられ、変えたマスは固定になります。印刷は A4 横。
- 入れた内容は、変わるたびにブラウザの中（`localStorage` の `shift:data:v1`）に保存されます。「ファイルに保存する」で JSON の1ファイルにできます。
