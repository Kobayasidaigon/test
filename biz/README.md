# 1人で運営できる、3つの小さな事業

1人で作って、1人で運営できる事業を3つ、「動く道具＋紹介のページ」の形まで作りました。どれもサーバーを持たず、ブラウザの中だけで動きます。入力された内容は、使う人のパソコンやスマホの外に出ません。

| フォルダ | サービス | だれの、どんな困りごとか | お金の入り方 |
| --- | --- | --- | --- |
| [`shift/`](shift/) | **たたき台シフト** | スタッフ5〜20人の個人経営の店の店長。毎月のシフト表を、Excel や紙で手で組んでいる。希望休と必要な人数を入れると、条件を守った「たたき台」をブラウザの中で数秒で組み、足りない日は理由を文で言う。 | 無料（スタッフ8人まで）／買い切り 4,980円（税込） |
| [`kaikei/`](kaikei/) | **ひきつぎ会計** | 町内会・子ども会・PTA・サークルの会計係（毎年交代するボランティア）。収入と支出を入れると、総会の資料5種類（収支決算書、出納帳、会計監査報告書、次年度の予算案、引き継ぎ書）が A4 で出る。次の担当には、ファイルを1つ渡すだけ。 | 入力と確認は無料／透かしなしの印刷と次年度への繰り越しは、1年度 980円（税込） |
| [`chintai/`](chintai/) | **みつもり点検** | 部屋を借りる人。不動産会社からもらった初期費用の見積書を、1行ずつ点検する。確かめたほうがよい行に赤ペンが入り、根拠の資料と、不動産会社に送る確認の文面（メール用・LINE用）が出る。 | 無料。広告（引越し・回線・火災保険の紹介）で運営。広告の枠は、提携が決まるまで空 |

なぜこの3つにしたか、ほかに何を比べたかは [`RESEARCH.md`](RESEARCH.md) にあります（9案を調べて、2人の審査役が点を付けた記録）。**どの案も、売上の見込みを裏付ける数字は見つかっていません。** 3つとも、小さく出して反応を測るための形です。

## 動かす

それぞれのフォルダで、別々に動きます。Node.js 20 以上が要ります。

```sh
cd biz/shift        # または biz/kaikei、biz/chintai
npm install
npm run dev            # 開発用。http://localhost:5173
npm run build          # ページごとの静的HTMLを dist/ に書き出す
npm run serve          # dist/ を http://localhost:4173 で確かめる
npm run build:single   # 全ページを dist-single/index.html の1ファイルにまとめる（ダブルクリックで開ける確認用）
npm test               # 計算と判定のテスト
npm run typecheck
```

くわしいこと（フォルダの中身、公開前にやること、ライセンスキーの発行のしかた）は、それぞれの `README.md` にあります。

## 3つに共通の作り

- **Vite + React + TypeScript + Tailwind CSS v4。** 見た目の部品は 21st.dev から取り入れ、サービスごとの世界観に合わせて作り変えています（何をどう変えたかは、それぞれの `CREDITS.md`）。
- **計算と判定は `src/core/` に、画面と分けて置いています。** テストもここにあります。
- **ページごとに静的HTMLを書き出します**（検索エンジンと SNS の共有のため）。道具の画面（`/app`）だけは、ブラウザで描きます。
- **データはブラウザの中（localStorage）と、利用者が保存したファイル（JSON）だけ。** 運営者はデータを見られず、なくなったデータを戻すこともできません。どの道具も、ファイルへの書き出しを目立つところに置いています。
- **有料版のライセンスキーは、サーバーなしで確かめます**（運営者の秘密鍵で署名し、ブラウザが公開鍵で確かめる。`scripts/license.mjs`）。公開鍵を入れるまでは「公開前モード」で、有料版の機能がすべて試せます。画面の中の制限なので、技術のある人は外せます。正直に買ってくれる人のための仕組みです。
- **うその実績や、根拠のない数字は書いていません。** 利用者の声、導入数、「No.1」などはありません。事実を書いたところには出典を付けています。

## 公開する前に、運営者がやること（3つに共通）

それぞれの `README.md` に、手順をくわしく書いてあります。ここでは、共通の大事なことだけ。

1. **`src/site.config.ts` の空の項目を埋める。** 公開する URL、運営者の名前・連絡先（特定商取引法の表記に出ます）、決済ページ（Stripe の Payment Link など）、ライセンスの公開鍵。
2. **出典を、公式のページを開いて確かめる。** この作業の環境からは、官公庁のサイト（e-Gov 法令検索、国土交通省、内閣府など）を直接開けませんでした。出典は、公式のサイトに絞った検索の抜き書きで確かめたものです。画面にも「検索で確認」と書いてあります。**特にみつもり点検は、根拠の文がそのまま判定に使われるので、確かめ終わるまで公開しないでください。**
3. **Chromium のほかのブラウザで確かめる。** 動かして確かめたのは Chromium（Chrome と同じしくみのブラウザ）だけです。Safari（iPhone・Mac）、Firefox、本物のスマホ、本物のプリンターでは試していません。
4. **サービス名の商標を確かめる。**「たたき台シフト」「ひきつぎ会計」「みつもり点検」は仮の名前で、同じ名前のサービスや商標の有無は調べていません（J-PlatPat などで）。
5. **置き場所を決める。** どのフォルダにも `vercel.json` があります。Vercel では、プロジェクトの「Root Directory」を `biz/shift` のように、そのフォルダにしてください（リポジトリの一番上の `vercel.json` は、別のサイト用です）。**Vercel の無料プラン（Hobby）は、お金を得ない個人の利用に限られます。** 有料版や広告があるこの3つは、Pro にするか、Cloudflare Pages など、商用で使える無料の置き場所を選んでください（`dist/` をそのまま置けば動きます）。

## できていないこと

- 公式ページの原文での確認（上の 2）と、Chromium のほかのブラウザでの確認（上の 3）。
- 決済から、キーをメールで送るまでの流れ。キーの発行と確認は通しましたが、Stripe での実際の支払いは試していません。キーは運営者が手作業でメールします（自動で送る仕組みはありません）。
- みつもり点検の広告は、提携先が決まっていないので、枠が空のままです。
- それぞれの `README.md` の「残っていること」に、細かい点を書いてあります。
