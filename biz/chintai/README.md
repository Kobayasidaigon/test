# みつもり点検

賃貸の部屋を借りるときにもらう、初期費用の見積書を、項目ごとに点検する道具です。サーバーはなく、ブラウザの中だけで動きます。

## このサービスは何か

- **だれの**: 一人暮らしや二人暮らしを始める、20〜30代の人。使われるのは、主に1〜3月。
- **どんな困りごと**: 不動産会社から見積書をもらったが、「高い気がするけれど、どれが必ずかかるお金で、どれが確かめたほうがよいお金なのか、わからない」。
- **どう解くか**:
  1. 見積書の項目と金額を、1行ずつ入れる（一覧から選ぶ／見積書の言葉で探す）。
  2. 行ごとに、「ふつうはかかる」「上限の決まりがある」「必須か任意か、確かめる」などの区分と、理由、根拠にした資料へのリンク、聞き方が出る。確かめたほうがよい行には、赤ペンが入る。
  3. 聞きたい項目を選ぶと、不動産会社に送る確認の文面（メール用・LINE用）ができる。結果は A4 で印刷できる。
- **言わないと決めていること**: 「払わなくてよい」「外せる」と断定しない。相場で高い安いを言わない。必ず下がるとは言わない。個別の法律相談はしない（相談先を案内する）。
- **料金**: 道具は無料。会員登録なし。有料版なし。収入は、広告（引越しの見積もり、インターネット回線、火災保険などのアフィリエイト）だけ。はじめは、広告の枠は全部空で、何も表示されない。

## 動かし方

```sh
npm install
npm run dev            # 開発用。http://localhost:5173
npm run build          # ページごとの静的HTMLを dist/ に書き出す
npm run serve          # dist/ を http://localhost:4173 で確認する（npm run build のあと）
npm run build:single   # 全ページを dist-single/index.html の1ファイルにまとめる（確認用。ダブルクリックで開ける）
npm test               # テスト（計算、項目のデータ、言い方、ページの書き出し）
npm run typecheck      # 型の検査
```

直したあとは、`npm run typecheck && npm test && npm run build` が通ることを確かめてください。

## ページ

| URL | 中身 | 作り方 |
| --- | --- | --- |
| `/` | ランディングページ（LP）。一番上で、サンプルの見積書に赤ペンが入る | 静的HTML |
| `/app` | 道具の画面（見積書を入れる → 点検の結果 → 確認の文面） | ブラウザで描く |
| `/items` | 項目の一覧（道具が知っている26個の項目を、区分ごとに） | 静的HTML |
| `/items/<項目>` | 項目ごとの解説（12ページ。敷金、仲介手数料、鍵の交換費用 など） | 静的HTML。`src/core/items.ts` のデータから作る |
| `/about` | このサイトについて（運営者、広告で運営していること、免責、相談先） | 静的HTML |

有料版がないので、特定商取引法にもとづく表記（`/tokushoho`）のページは、ありません。

## フォルダの中身

- `src/site.config.ts` … サービス名、公開する URL、運営者の情報、サイトを置くサーバーの会社（`hosting`）、料金と売り方（`pricing`）。**公開前に埋める項目は、ここに集めてあります。**
- `src/routes.ts` … ページの一覧と、検索結果に出る題・説明文。ここに足したページが `dist/<パス>/index.html` になる。解説ページは、項目のデータから自動で足される。
- `src/core/` … 中身のロジックとデータ（項目のルール、出典、点検、確認の文面、保存の形式）。画面に依存しない。くわしくは `src/core/README.md`。
  - `items.ts` … 項目の一覧と、解説ページの文。`sources.ts` … 根拠にしている資料（出典）。`texts.ts` … 免責など、どの画面でも同じ言い方をする文。`wording.ts` … 言ってはいけない言い方の一覧。
- `src/offers.ts` … 広告の枠。`url` が空の枠は、表示しない（はじめは全部空）。
- `src/pages/` … ページ。`Landing.tsx`（LP）、`Tool.tsx`（道具）、`Items.tsx`（項目の一覧）、`ItemGuide.tsx`（項目ごとの解説。1つの部品で12ページ分）、`About.tsx`、`Privacy.tsx`。
- `src/components/landing/` … LP の欄（一番上、何がわかるか、使い方、文面の見本、しないこと、資料の一覧、解説への入口、運営、よくある質問）。
- `src/components/site/` … LP とその他のページに共通の、上の帯（`site-header.tsx`）、フッター（`site-footer.tsx`）、その他のページの枠（`page-shell.tsx`）。
- `src/components/guide/` … 解説ページだけに置く部品（仲介手数料の、小さな点検）。
- `src/components/tool/` … 道具の画面の組み立て（手順1〜3、保存、ファイルの書き出しと読み込み）。
- `src/components/` … このサービスの部品。赤ペンの線（`pen.tsx`）、紙（`sheet.tsx`）、赤ペンが入った見積書（`inspected-sheet.tsx`）、1行ごとの結果（`finding-card.tsx`）、区分の印（`category-mark.tsx`）、出典（`source-link.tsx`）、相談先（`consult-desks.tsx`）、便せん（`message-preview.tsx`）、広告の枠（`offer-slot.tsx`）、サイトの印（`brand.tsx`）。
- `src/components/ui/` … 21st.dev から取り入れて、作り変えた部品（一覧と、どう変えたかは `CREDITS.md`）。
- `src/index.css`、`index.html` … 見た目の土台（「見積書に、赤ペンで点検を入れる」）。色（机 `desk`、紙 `paper`、インク `ink`、赤ペン `pen`、蛍光ペン `marker`、えんぴつ `pencil`）、書体、紙、印刷（A4）の決まり。
- `public/` … `favicon.svg`（サイトの印）、`og.png`（リンクを貼ったときに出る共有画像）、`robots.txt`。
- `scripts/` … `prerender.mjs`（静的HTMLの書き出し）、`serve.mjs`（手元の確認用サーバー）、`og.html`（共有画像のもと）。

LP に出ている見積書・点検の結果・文面は、撮った画像や手で書いた見本ではなく、道具と同じ部品に、道具と同じロジックの結果を渡したものです。`src/core/` を直せば、LP も解説ページも、一緒に変わります。

## 公開の前に、運営者がやること

上から順に進めてください。1〜3 が終わるまでは、公開しないでください。

### 1. 根拠にしている資料を、1つずつ開いて確かめる（いちばん大事）

この道具は、まちがえると人に損をさせます。点検の結果に出す「根拠」は、法令と、国・自治体などの資料に書かれていることだけ、と決めています。

**ただし、2026年11月14日の確認は、資料のページを直接開いて行ったものではありません。** 作業した環境から官公庁のサイトを開けなかったため、検索の対象を公式サイトに絞り、検索結果に出た本文の抜粋で確かめました（`src/core/sources.ts` の `verifiedBy: 'official-site-search'`）。検索の要約どうしが食い違った例も、1つありました。公開の前に、人の目で確かめ直す必要があります。

同じ日に、点検の担当が、もう一度、別の検索で確かめ直しました。そのとき確かめられなかった文（「礼金は返ってこない」の出典、「払った更新料は返ってこない」）は、出典を付けかえるか、消してあります。

**いまの画面には、この確かめ方を、そのまま書いてあります。** 資料の一覧・解説ページ・点検の結果・「このサイトについて」に、「資料のページそのものを開いての確認は、まだ済んでいません」ということわり書きが出て、出典ごとの表示は「○年○月○日に、検索で確認」になっています（`sources.ts` の `VERIFY_METHOD_NOTE` と `verifiedLabel`）。下の手順で原文を確かめると、このことわり書きは消えます。

やり方:

1. `src/core/sources.ts` を開く。資料が18件並んでいる。それぞれの `url` を、ブラウザで開く。
2. `src/core/items.ts` を開く。上のほうの `const B = { … }`（根拠の文）と `const R = { … }`（参考の文）に、文と、その出典（`sourceIds`）が並んでいる。**文の1つずつについて、出典の資料に、そのとおりのことが書かれているかを確かめる。**
   - 特に、言い回しまでは見られていないもの: 民法 第621条・第622条の2 の条文、保証会社、礼金、敷引き、国民生活センターの注意喚起、重要事項説明書の様式についての文。
   - 仲介手数料の「0.55倍・1.1倍」「依頼のときの承諾」は、国土交通省の告示の本文でも確かめる。
3. 資料と合わない文があったら、資料に合わせて直す。確かめられない文は、消す。その項目に根拠の文が1つも残らなければ、その項目の `basisStatus` を `'none-found'` に、`basis` を `[]` にする（道具は「決まりは見つかりませんでした」と伝える）。
4. URL が変わっていたら、`sources.ts` の `url` を直す。
5. 原文で確かめた資料は、`sources.ts` のその資料に、次の2行を書く（`...on,` のすぐ下に書けば、上書きされる）。出典ごとの表示が「○年○月○日に、原文で確認」に変わる。

   ```ts
   ...on,
   verifiedBy: 'official-page',
   verifiedOn: '2027-01-10',   // 確かめた日。'2027-01-10' の形で
   ```

   1件ずつ書いていってかまわない。途中のあいだ、画面のことわり書きは「18件のうち○件は、…まだ済んでいません」と、残りの件数を言う。`const on = { … }` は、直さなくてよい。
6. 全部確かめたら、`sources.ts` の `RULES_VERIFIED_ON` を、最後に確かめた日（`'2027-01-10'` の形）に直す。この日付が、道具・LP・解説ページの「ルールの最終確認日」に出る。18件すべてが `'official-page'` になると、「まだ済んでいません」のことわり書きが、全部の画面から消える。
   - 出典の `verifiedOn` を書くより先に、`RULES_VERIFIED_ON` だけを新しい日にすると、テストが落ちる（どの出典も確かめていない日を、「最終確認日」として出さないため）。
7. 原文の言い回しを、かぎかっこ（「」）で引きたいときは、その出典を `'official-page'` にしてから引く。いまの根拠の文は、原文を開けていないので、「〜という趣旨の記載があります」という言いかえで書いてある（検索の抜粋だけで、1字ずつの引用はしない）。
8. `npm test` を実行する。落ちたら、下の「テストが落ちたとき」を見る。

確かめられなかったので、ルールに入れていないこと（仲介手数料の計算のもとに管理費を含めるかどうか、など）は、`src/core/README.md` の最後の表にあります。

#### テストが落ちたとき

テストは、「いまの値」ではなく、「形と決まり」を確かめています。上の手順（出典を原文で確かめる）、下の「4. 広告を入れる」「7. 項目を足す・直す」のとおりに直しただけなら、落ちません。落ちたときは、テストの名前と、いっしょに出る日本語の文を読んでください。何を直すかが書いてあります。

| 落ちたテスト（ファイル） | よくある原因 | 直し方 |
| --- | --- | --- |
| 「出典の確かめた日・確かめ方と、ルールの最終確認日の、つじつまが合っている」（`src/core/items.test.ts`） | `verifiedOn` の形が `'2027-01-10'` でない／今日より先の日／`RULES_VERIFIED_ON` が、どの出典の `verifiedOn` よりも新しい | 出る文のとおりに、日付を直す |
| 「かぎかっこ（「」）での引用は、原文で確かめた出典の文にだけ使う」（同じ） | 原文で確かめていない出典の文に、「」の引用を足した | 出典を原文で確かめて `'official-page'` にするか、言いかえにする |
| 「根拠の文には、必ず出典がある」「言ってはいけない言い方がない」（同じ） | 出典のない文、断定の言い方（「外せます」など）を足した | 出典を付ける。言い方を、「確かめる」「聞いてみる」の形にする |
| 「url を入れた枠は、…表示できる」「広告の見出しと説明に、…」（`src/offers.test.ts`） | 広告の `url` が `https://` で始まっていない／`title` が空／「No.1」「最安」などの言い方 | 出る文のとおりに直す |
| 「題と説明文が、検索結果に出て意味が通る長さになっている」（`src/pages/pages.test.ts`） | 足した解説ページの題や説明文が、短すぎる・長すぎる | 題は15〜45字、説明文は80〜120字にする |

### 2. `src/site.config.ts` の空の項目を埋める

| 項目 | 入れるもの | 空のままだと |
| --- | --- | --- |
| `baseUrl` | 公開する URL。`'https://example.jp'` の形（最後に `/` を付けない） | 検索エンジン向けの情報（正式な URL、共有画像の場所、`sitemap.xml`）が書き出されない |
| `operator.name` | 運営者の名前（個人の名前か、屋号） | `/about` に「（公開前に記入します）」と出る |
| `operator.email` | 連絡先のメールアドレス | `/about` と `/privacy` に「（公開前に記入します）」と出る |
| `contact` | お問い合わせ先（メールアドレスか、フォームの URL）。`operator.email` を入れたら、空でよい | — |
| `hosting.name` | サイトを置くサーバーの会社（ホスティング会社）の名前。Vercel に置くなら `'Vercel Inc.'` | `/privacy` の「サイトを置いているサーバーの記録」に「（公開前に記入します）」と出る |
| `hosting.privacyUrl` | その会社のプライバシーポリシーの URL（`https://` で始まるもの）。入れると、会社の名前がリンクになる | 会社の名前だけが出る |

`pricing` の文（無料、登録なし、広告で運営）は、そのままで使えます。事実が変わったときだけ、直してください。`slug` は、保存領域の名前に使っているので、変えないでください。

埋めたら、`npm run build && npm run serve` で `/about` と `/privacy` を開き、運営者の表記が出ていることを確かめます。

`/privacy` には、ページを配るサーバー（ホスティング会社）に、アクセスの記録（IP アドレス、ブラウザの種類など）が残ることを書いてあります。使う会社が決まったら、その会社が何を記録するかを確かめて、文が合っているかを見てください（`src/pages/Privacy.tsx` の「サイトを置いているサーバーの記録」）。

### 3. 決済ページと、ライセンスの鍵について

**このサービスには、どちらもありません。** 道具は無料で、有料版がないので、決済ページ（Stripe など）のリンク、ライセンスの鍵の作成、ライセンスキーの発行は、何もしなくてかまいません（土台にあった仕組みは、消してあります）。

かわりに、収入のための作業は、次の「広告を入れる」だけです。広告がなくても、サイトは公開できます。

### 4. 広告を入れる（提携できたら）

1. アフィリエイトの会社（ASP）や、紹介したいサービスと提携する。
2. `src/offers.ts` を開く。枠が3つある（引越しの見積もり `hikkoshi`、インターネット回線 `net`、火災保険 `hoken`）。提携できた枠に、次の3つを入れる。
   - `url` … 広告のリンク（`https://` で始まるもの）。
   - `title` … 広告の見出し。**事実だけを書く**（「No.1」「最安」などは、根拠がなければ書かない）。
   - `description` … ひとことの説明。事実だけ。
3. `npm run build && npm run serve` で、下の表の場所に、**「広告」と書かれた枠**で出ることを確かめる。「広告」の表示は、自動で付きます（消さないでください。2023年10月から、広告であることを隠す表示は、景品表示法違反になります）。

   | 枠 | 点検の結果の画面（`/app`） | 解説ページ（`/items/…`） |
   | --- | --- | --- |
   | `hikkoshi`（引越しの見積もり） | 出る | **すべての解説ページ**に出る |
   | `net`（インターネット回線） | 出る | 出ない |
   | `hoken`（火災保険） | 出る | 火災保険料のページ（`/items/kasai-hoken`）だけに出る |

   検索から来た人が最初に開くのは、解説ページです。解説ページに出る枠が1つもないと、道具を最後まで使った人にしか、広告が見えません。そのため、引越しの枠は、すべての解説ページに出るようにしてあります。
   出す場所を変えるときは、`offers.ts` の `placements`（`'result'` ＝ 結果の画面、`'item'` ＝ 解説ページ）と `itemIds`（解説ページをしぼる項目。空なら、すべての解説ページ）を直します。たとえば、インターネット回線の枠も解説ページに出すなら、`placements: ['result', 'item']` にします。LP（`/`）と「このサイトについて」には、広告の枠はありません。
4. 提携先の決まりで、プライバシーポリシーに書くことがあれば、`src/pages/Privacy.tsx` の「広告について」の段に足す。
5. 広告配信やアクセス解析のためのタグ（スクリプト）は、入れないでください。入れる場合は、「入れていません」と書いている `src/pages/About.tsx`、`src/pages/Privacy.tsx`、`src/routes.ts`（`/privacy` の説明文）を、先に直す必要があります。

`url` を空に戻せば、その枠は表示されなくなります。

### 5. ドメインを取って、公開する

Vercel に置く場合の手順です（`vercel.json` が入っています。ほかの静的サイトのサービスでも、`npm run build` でできる `dist/` を置けば動きます）。

1. ドメインを取る（お名前.com、Cloudflare など）。
2. このフォルダを、GitHub のリポジトリに置く。
3. Vercel（vercel.com）で、アカウントを作り、「Add New → Project」から、そのリポジトリを選ぶ。
   - リポジトリの中の一部だけがこのフォルダのときは、「Root Directory」に、このフォルダ（`biz/chintai`）を指定する。
   - ビルドのコマンドと出力先は、`vercel.json` から自動で入る（`npm run build`、`dist`）。
4. 「Deploy」を押す。数分で、`〜.vercel.app` の URL で見られるようになる。
5. Vercel の「Settings → Domains」で、取ったドメインを足し、画面に出る案内のとおりに、ドメインの会社の管理画面で DNS を設定する。
6. `src/site.config.ts` の `baseUrl` を、そのドメインに直して、もう一度公開する（GitHub に push すれば、自動で公開される）。
7. `https://<ドメイン>/sitemap.xml` が開くことを確かめ、Google Search Console に登録して、サイトマップを送る。

### 6. 公開の前後に、確かめておくこと

- [ ] `npm run typecheck && npm test && npm run build` が通る。
- [ ] 全部のページを開く（`/`、`/app`、`/items`、解説の12ページ、`/about`、`/privacy`）。運営者の表記に「（公開前に記入します）」が残っていない。
- [ ] 道具で、自分の手元の見積書を1つ、最初から最後まで入れてみる（入力 → 結果 → 文面のコピー → 印刷 → ファイルに書き出す → 読み込む）。
- [ ] **iPhone の Safari と、Android の Chrome で開く。** これまでの確認は、パソコンの Chromium だけで行っています。見るところ: 入居する日の入力欄、項目を探すときにキーボードが候補を隠さないか、LP の一番上で赤ペンが入る動き、手書きの書体の読みやすさ。
- [ ] Safari と Firefox（パソコン）でも、LP と道具を開く。
- [ ] リンクを SNS やメッセージアプリに貼って、共有画像（`og.png`）が出ることを確かめる（`baseUrl` を入れて公開したあとでないと、出ません）。

- [ ] **書体の重さ。** 最初のページで、書体だけで約1.5MB（約90ファイル）を読み込みます（自分のファイルは、あわせて150KBほど）。文字はすぐに出ますが（書体が届くまでは、端末の書体で出る）、スマホの回線では、書体が入れかわるまで時間がかかります。気になるときは、(a) 本文を端末に入っている書体にして、BIZ UDPGothic は見出しと見積書の紙だけに使う、(b) 使う文字だけにしぼった書体のファイルを作って、自分のサーバーから配る、のどちらかで軽くできます。見た目が変わるので、まだ手を付けていません。

### 7. 公開したあと、続けること

- **ルールの見直し**: 法令や資料は変わります。年に1回（借りる人が増える1月の前がおすすめ）と、仲介手数料や原状回復のガイドラインが変わったという知らせを見たときに、上の「1」をもう一度行い、確かめた出典の `verifiedOn` と、`RULES_VERIFIED_ON` を直してください。
- **項目を足す・直す**: `src/core/items.ts` に項目を足します。`guide`（解説ページの中身）を付けると、解説ページ、一覧、フッター、道具の結果からのリンクが、自動で増えます（ページの数に、上の限りはありません）。事実を書くときは、必ず出典（`sources.ts`）を付けてください。出典のない文は、テストで落ちます。見積書での別の呼び方を足すときは、その項目の `aliases` に足します（道具の「見積書の言葉から探す」で、見つかるようになります）。
- **共有画像を作り直す**: `scripts/og.html` を直して、ブラウザで開き、画面を 1200×630 にして、画像として保存し、`public/og.png` に置きます。Playwright が使える環境なら、次のコマンドで作れます。

  ```sh
  npx playwright screenshot --viewport-size=1200,630 --wait-for-timeout=2000 scripts/og.html public/og.png
  ```

## お金の入り方（まとめ）

道具は無料で、登録もいらない。有料版・ライセンスキー・決済ページはない。収入は広告（アフィリエイト）だけで、広告の枠は `src/offers.ts` にまとめてある。広告には、必ず「広告」と表示する。点検の結果（`src/core/`）は、広告の枠を見ないので、広告があってもなくても、結果は変わらない。
