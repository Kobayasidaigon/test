# 住む街ガチャ — デザイン試作のブリーフ（全案共通）

## 何を作るか
「住む街ガチャ」（名前は決定）。家族構成・世帯年収・働き方・今の街を入れると、引っ越し先の候補の街ごとに「その家族にとって年にいくら得か・損か」が出る。ゲームのように楽しく、でも出てくる情報は噛み砕いて分かりやすく。

今回はデザインの試作。1つの案＝1つの世界観で、入力 → ガチャの演出 → 結果 までを、スマホで触れる形で作る。

## ユーザー（サイトの運営者）からの要望
- 動きをたくさん入れたい。
- プラスなら家族が喜ぶ、マイナスなら悲しくなる、など結果を感情で見せたい。
- 県や仕事に有名なもの（名産・産業・仕事）があれば、それをいい感じに表現したい。
- 家族構成や世帯年収なども入力させて、噛み砕いた情報が出るゲームっぽい体験にしたい。
- 「AIで作ったとまるわかり」な見た目は避けたい。

## 事前調査で決めたルール（必ず守る）
1. **結果は計算で決まる。** ガチャは演出で、ランダムではない。課金もない。「当たり」「ハズレ」「レア」「SSR」などの言葉や、レア度の表現は使わない。
2. **悲しむのは貯金箱（家族の財布）だけ。** 町・名物・子どもは悲しませない。子どもを泣かせない。「負け」「損な町」「ワースト」は使わない。
3. **マイナスの結果は、前向きに言い換える。** 例: 「足立区のままが、年 約30万円お得」「今の街、実はかなり手厚い！」。最後は必ず「次の一歩」で終わる。
4. **毎年の差と、一度きりのお金を混ぜない。** 移住支援金などの一度きりのお金は、別の枠（「一度きり」）で見せる。表情は毎年の差（comparison.mood）だけで決める。
5. **確かめていない項目は 0円にしない。** comparison.unknown にある項目は「確認中」として見せる。
6. **数字には確からしさを付ける。** item.confidence（確認済／推定／仮置き）を小さく表示し、出典（item.sources）をタップで見られるようにする。
7. **免責を必ず出す。** 結果画面に DISCLAIMER（@/shared の定数）を表示する。
8. **広告の枠は「PR」と明記する。** 試作では本物のリンクは入れず、「PR（提携後に表示）」の仮の枠にする。結果の数字と広告は、背景色などで分ける。
9. **入力は端末の中だけで使う。** 送信しない。
10. **入力例は入力例と書く。** 初期値の家族は「入力例」と分かるようにする。

## データと計算（@/shared から使う。中身は変えない）
- `rank(input)` … 候補の街を、毎年の差が大きい順に並べた `Comparison[]`
- `compare(input, from, to)` … 2つの街の比較
- `Comparison` … headline（例「草加市なら、年 約50万円 得」）、subline、perYear、total、oneTime、items（Breakdown[]）、unknown、mood（-2〜2）、from、to
- `Breakdown` … label、icon（nursery/cash/lunch/medical/iju）、perYear、total、oneTime、confidence、who（例「1歳の子」）、plain（噛み砕いた説明）、detail（計算の中身）、sources
- `everyday(yearly)` … 年額を「月 約◯円」「1日 約◯円」に言い換える
- `MOOD_TEXT[mood]` … 表情ごとの一言
- `CITIES`、`cityById(id)` … 街のデータ。`city.pride` に名物・有名なもの（label、kind、fact、confidence）
- `INCOME_BANDS`、`WORK_STYLES`、`SAMPLE_INPUT`、`SAMPLE_INPUT_REMOTE`、`DISCLAIMER`、`DATA_AS_OF`、`yenMan(yen)`
- 型は `@/shared/types` を見る。

調査で分かった、看板になる事実（コピーに使ってよい）:
- 東京都は 0〜2歳の保育料が第1子から0円（2025年9月〜）。隣の埼玉の市だと、世帯年収600〜800万円・1歳の第1子で年 約50〜60万円かかる（推定）。
- 東京都は 018サポートで子ども1人に月5,000円（年6万円）。
- 大阪市は 0〜2歳の第1子も2026年9月から0円。
- 札幌市の移住支援金は世帯60万円＋子1人10万円（令和8年度）。

## 体験の流れ（どの案も）
1. **スタート画面**: 「住む街ガチャ」の名前と、何ができるかの一文、はじめるボタン。
2. **入力（ゲームっぽく、1画面1問くらい）**: 家族（大人1〜2人、子ども0〜5人、年齢0〜18歳か「これから生まれる」、0〜2歳の子は保育園に通うか）、世帯年収（5段階）、働き方（4種類）、今住んでいる街（CITIES から選ぶ）、比べる期間（1年／5年／下の子が18歳まで）。
3. **ガチャの演出**: 2〜4秒。スキップできる。動きを減らす設定の人には出さない。
4. **結果**: いちばん上の候補（と今の街の比較）、headline、家族の表情、項目ごとの噛み砕いた説明、月・1日への言い換え、確認中の項目、一度きりのお金、名物・有名なもの（city.pride）、ほかの候補の並び、「次の一歩」（PRの仮の枠）、「条件を変えてもう1回」、免責。
5. **`?step=result` で、入力例（SAMPLE_INPUT）の結果画面へいきなり飛べること**（スクリーンショット用）。`?step=result&sample=remote` なら SAMPLE_INPUT_REMOTE。演出は飛ばしてよい。

## 技術の決まり
- React 18 + TypeScript + Tailwind CSS v4 + motion（`import { motion, AnimatePresence } from 'motion/react'`。`framer-motion` も入っている）。
- 入っているライブラリだけを使う: motion / framer-motion、lucide-react、clsx、tailwind-merge、class-variance-authority、canvas-confetti、@number-flow/react、@radix-ui/react-slider、@radix-ui/react-slot。**npm install はしない。** ほかのライブラリが要る部品は、自分で同じ考え方を作り直す。
- `@/lib/utils` の `cn`、`@/components/ui/`（button、card、badge、slider）は使ってよい（編集はしない）。
- 自分の案のファイルだけを編集する: `src/variants/<案>/` 以下と、`<案>.html`（Google Fonts の link を `<!-- FONTS:<案> -->` の位置に入れる）。**ほかの案のファイル、src/shared、src/components、設定ファイルは編集しない。**
- 使った Google Fonts の URL を `src/variants/<案>/fonts.txt` に1行で書く（あとで全案をまとめるときに使う）。
- 21st から持ってきた部品は、ファイルの先頭のコメントと `src/variants/<案>/CREDITS.md` に、部品名・作者・URL・どう変えたかを書く。
- 型チェック: `npx tsc --noEmit -p tsconfig.<案>.json`
- ビルド: `node scripts/build-variant.mjs <案>` → `dist-<案>/<案>.html`（1ファイル）
- スクリーンショット: `node scripts/shoot.cjs <案> <出力フォルダ>` → 入力画面と結果画面を 390px と 1440px で撮る（エラー、横スクロール、読み込めたフォントも出る）。
- スマホ（390px）を主役にする。1440px でも崩れないこと（真ん中にスマホ幅で置く、または広げる）。横スクロールを出さない。
- アクセシビリティ: ボタンにラベル、フォーカスが見える、動きを減らす設定への対応、文字のコントラスト、結果は aria-live で読み上げられる。

## 「AIっぽさ」を避ける
- 紫〜青のグラデーション、すりガラス、どこにでもあるカードの3列並び、絵文字をアイコン代わりに使うこと、Inter などの無難なフォントは避ける。
- 絵はSVGやCSSで、その案の世界観に合わせて自分で描く（家族のキャラ、貯金箱、名物など）。
- 日本語は、人が話すように短く具体的に。「〜しましょう！」の連発や、決まり文句は避ける。
